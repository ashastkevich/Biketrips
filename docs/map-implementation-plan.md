# BikeTrips: план внедрения карт

## Цель

Внедрить карту на базе MapLibre GL JS с внешней подложкой и геокодингом MapTiler. Первый инкремент заменяет прототип карты в визарде создания поездки и позволяет выбрать точку старта. Архитектура должна допускать последующее отображение GPX-маршрутов, маршрутных точек и переход на собственные PMTiles без замены UI-компонентов.

## Принятые решения

- Движок карты: MapLibre GL JS.
- Подложка на первом этапе: MapTiler Cloud.
- Поиск и обратное геокодирование на первом этапе: MapTiler Geocoding API.
- Формат прикладных геоданных: GeoJSON.
- Координаты в API и доменной модели: числа в WGS84 (`longitude`, `latitude`).
- Секретный серверный ключ не используется в браузере. Публичный MapTiler-ключ ограничивается разрешёнными доменами и хранится в `NEXT_PUBLIC_MAPTILER_API_KEY`.
- Компоненты карты загружаются динамически только там, где они нужны.
- Код MapLibre не должен напрямую зависеть от конкретного геокодера. Доступ к поиску оформляется через адаптер.

## Текущее состояние

В проекте уже есть большая часть сквозного контракта точки старта:

- визард хранит `startLocationName`, `startLat` и `startLng`;
- скрытые поля передают координаты при отправке формы;
- `CreateTripInput` и backend DTO принимают координаты;
- PostgreSQL хранит координаты с шестью знаками после запятой;
- serializer возвращает координаты числами.

Компонент `StartLocationPicker` сейчас рисует условную карту CSS-средствами, вычисляет координаты по позиции клика и генерирует фиктивный адрес. Его нужно заменить реальной картой и обратным геокодированием.

## Этап 1. Выбор точки старта в визарде

### 1. Конфигурация и зависимости

1. Добавить в `apps/web` зависимости:
   - `maplibre-gl`;
   - клиент или geocoding control MapTiler — только если он потребуется для обратного геокодирования; предпочтительно начать с небольшого собственного адаптера HTTP API.
2. Добавить `NEXT_PUBLIC_MAPTILER_API_KEY` в `.env.example` и документацию локального запуска.
3. Настроить ограничения публичного ключа по доменам для production, preview и localhost.
4. Не инициализировать карту при отсутствии ключа: показывать понятное состояние конфигурационной ошибки.

### 2. Границы модулей

Добавить структуру:

```text
apps/web/app/maps/
  map-types.ts
  map-config.ts
  maptiler-geocoder.ts
  interactive-map.tsx
  interactive-map-loader.tsx
```

- `map-types.ts` — `MapPoint`, `MapBounds`, интерфейс геокодера и результаты поиска.
- `map-config.ts` — URL стиля, начальный zoom и безопасное чтение публичной конфигурации.
- `maptiler-geocoder.ts` — прямое и обратное геокодирование без UI-зависимостей.
- `interactive-map.tsx` — client-only оболочка MapLibre, lifecycle карты, resize и cleanup.
- `interactive-map-loader.tsx` — динамический импорт с отключённым SSR и состоянием загрузки.

`StartLocationPicker` остаётся компонентом сценария визарда: он управляет выбранной точкой, текстом адреса, ошибками геокодинга и передаёт данные наверх через существующий `onChange`.

### 3. Поведение карты

1. При открытии центрировать карту:
   - на уже выбранной точке, если координаты есть;
   - иначе на центре выбранного города;
   - иначе на центре Москвы как безопасном fallback.
2. По клику на карту:
   - немедленно переместить единственный маркер;
   - сохранить координаты с точностью до шести знаков;
   - запустить обратное геокодирование;
   - после ответа сохранить человекочитаемый адрес.
3. Пока адрес загружается, показывать состояние «Определяем адрес…», не блокируя перемещение карты.
4. Если геокодер недоступен:
   - сохранить выбранные координаты;
   - показать неблокирующее предупреждение;
   - использовать подпись вида `55.751244, 37.618423`;
   - дать повторить определение адреса.
5. Повторный клик должен отменять или игнорировать устаревший запрос геокодинга, чтобы медленный ответ не перезаписал более новую точку.
6. При смене города:
   - если точка ещё не выбрана, переместить камеру к новому городу;
   - если точка уже выбрана, не менять её автоматически и не терять пользовательский ввод.
7. Добавить стандартные кнопки масштабирования. Геолокацию пользователя в первый инкремент не запрашивать.

### 4. Валидация и доступность

- Для продолжения визарда требовать одновременно `startLocationName`, `startLat` и `startLng`.
- На backend валидировать диапазоны:
  - latitude: от `-90` до `90`;
  - longitude: от `-180` до `180`.
- Маркер должен быть различим на светлой и тёмной части подложки.
- Контейнер карты получает доступное имя, а выбранный адрес и координаты доступны вне canvas.
- Ошибки выводятся через `role="alert"` или `aria-live`.
- Управление zoom доступно с клавиатуры; выбор точки с клавиатуры можно поддержать отдельной кнопкой «Поставить точку в центре карты».
- Учесть `prefers-reduced-motion` при анимации камеры.

### 5. Стили и mobile-first поведение

- Сохранить текущую высоту и скругление блока как исходный визуальный baseline.
- На мобильном экране не перехватывать вертикальную прокрутку страницы до явного взаимодействия с картой.
- Проверить карту на ширинах 320, 375, 768 и 1280 px.
- После изменения размера контейнера вызывать `map.resize()`.
- Attribution MapTiler/OpenStreetMap должна оставаться видимой и не перекрываться элементами визарда.

### 6. Тестирование первого этапа

Unit-тесты:

- преобразование ответа геокодера в `MapPoint`;
- форматирование координат;
- проверка диапазонов координат;
- защита от устаревших ответов геокодинга;
- fallback при сетевой ошибке.

Компонентные тесты/Storybook:

- карта без выбранной точки;
- карта с сохранённой точкой;
- загрузка адреса;
- ошибка геокодера;
- отсутствующий API-ключ;
- смена города с выбранной и невыбранной точкой.

Ручная проверка:

- клик создаёт и перемещает только один маркер;
- адрес и координаты попадают в draft и сохраняются после переходов «Назад/Продолжить»;
- опубликованная поездка содержит те же координаты в API и БД;
- карта корректно очищается при размонтировании;
- нет повторной инициализации карты при обычных обновлениях React;
- страница не получает заметного layout shift;
- ключ не обладает правами, не нужными браузерному приложению.

### 7. Критерии готовности первого этапа

- CSS-прототип полностью заменён интерактивной картой.
- Пользователь выбирает точку кликом и видит маркер.
- Визард получает реальные координаты и человекочитаемый адрес.
- Ошибка геокодинга не уничтожает выбранную точку.
- Координаты проходят валидацию web и API и сохраняются в существующие поля БД.
- Карта работает на desktop и mobile.
- `npm run lint`, `npm run typecheck`, `npm test` и `npm run build` проходят.
- В документации описаны переменная окружения и настройка доменных ограничений ключа.

## Этап 2. Поиск места старта

После стабилизации выбора кликом:

1. Добавить строку поиска с debounce и отменой устаревших запросов.
2. Ограничивать результаты текущей страной и приоритетной областью выбранного города.
3. При выборе результата перемещать камеру, ставить маркер и сохранять нормализованные координаты и подпись.
4. Не смешивать данные поиска с доменной моделью: хранить у поездки только собственную подпись и координаты, если условия провайдера не разрешают сохранять дополнительные поля.
5. Добавить rate limiting на серверный proxy, только если поиск нельзя безопасно и корректно выполнять с публичным браузерным ключом.

## Этап 3. Отображение точки на карточке поездки

1. Создать read-only режим общего компонента карты.
2. Показывать точку старта на публичной карточке поездки.
3. Загружать карту лениво после попадания блока в viewport или по действию пользователя.
4. Предусмотреть ссылку «Открыть в навигаторе» отдельно от внутреннего компонента карты.

## Этап 4. GPX-маршрут

1. Загружать исходный GPX в существующее S3-compatible хранилище.
2. Валидировать размер, MIME type, XML и разумное максимальное количество точек.
3. Преобразовывать GPX в нормализованный GeoJSON `FeatureCollection`.
4. Хранить исходный GPX как файл, а вычисленные метаданные — отдельно:
   - дистанция;
   - набор границ;
   - старт и финиш;
   - набор высот, если он присутствует;
   - упрощённая геометрия для быстрого web-просмотра.
5. Отображать маршрут как `GeoJSONSource` и line layer MapLibre.
6. Автоматически выбирать bounds всего маршрута с мобильными padding.
7. Стилизовать линию маршрута, старт, финиш и направление движения.
8. Для длинных треков выполнять упрощение геометрии на backend, сохраняя исходный GPX для скачивания.

## Этап 5. Маршрутные точки и профиль высот

- Добавить типы точек: остановка, вода, ремонт, опасность, достопримечательность.
- Хранить точки как собственные сущности с координатами, типом, порядком и описанием.
- Отдавать их клиенту одной GeoJSON-коллекцией.
- Для большого количества точек использовать symbol/circle layers и clustering, а не отдельный React-компонент на каждую точку.
- Добавить профиль высот и синхронизацию курсора профиля с позицией на маршруте.

## Этап 6. Независимость от поставщика и PMTiles

Переход оправдан при заметной стоимости внешних тайлов, требованиях автономности или необходимости специальной велосипедной подложки.

1. Подготовить OSM-derived набор данных и MapLibre style.
2. Сформировать региональный или российский PMTiles-архив.
3. Разместить его в S3/CDN с корректной поддержкой HTTP Range Requests и CORS.
4. Переключить URL стиля через конфигурацию, не меняя компоненты MapLibre и GeoJSON-слои.
5. Оставить геокодер заменяемым: MapTiler, другой коммерческий сервис или собственный сервис.
6. Организовать регулярное обновление тайлов и контроль версии данных.

## Риски и меры

| Риск | Мера |
|---|---|
| API-ключ используется с чужого домена | Ограничить разрешённые origins и настроить квоты |
| Геокодер отвечает медленно | Маркер и координаты сохранять до получения адреса |
| Старый ответ перезаписывает новую точку | `AbortController` или монотонный request id |
| MapLibre увеличивает initial bundle | Динамический импорт только в компоненте карты |
| Карта ломается при SSR | Инициализация только в client component после mount |
| Ошибка внешнего провайдера блокирует создание поездки | Разрешить координатный fallback и повтор запроса |
| Публичные OSM-сервисы блокируют production-нагрузку | Использовать MapTiler, а не публичные tile/Nominatim endpoints |
| Будущая смена провайдера требует переписывания UI | Собственные типы и адаптеры геокодинга |
| GPX перегружает браузер | Проверка, нормализация и упрощение на backend |

## Рекомендуемый порядок реализации

1. Конфигурация MapTiler и доменные типы карты.
2. Базовая client-only MapLibre-оболочка.
3. Реальный `StartLocationPicker` с одним маркером.
4. Обратное геокодирование и обработка гонок/ошибок.
5. Усиление web/API-валидации координат.
6. Unit, Storybook и ручные responsive-проверки.
7. Документация локального запуска и production-ключа.
8. Только после приёмки первого этапа — поиск по строке.
